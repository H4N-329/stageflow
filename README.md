# StageFlow — ダンスショーケース立ち位置管理アプリ

ダンスショーケースの立ち位置、バミリ、時間ごとのフォーメーション、移動経路を確認するWebアプリです。ブラウザ内ではサーバー設定なしで使用でき、SupabaseとVercelを連携すると作品を共有できます。

## できること

- ステージ横幅（2〜40m）、奥行（2〜30m）、バミリ間隔（0.25〜5m）を自由設定（バミリの中心は0）
- 客席側が画面上・画面下のどちらかを指定
- 最大30名のダンサーを円で表示。名前の変更、自由な色指定、ドラッグ移動
- 時刻（秒）ごとに立ち位置を登録。前後の登録時刻の間は直線・等速で自動補間
- ±1秒送り、再生、タイムラインの移動、経路線表示
- 設定距離より近づく可能性を、各登録区間で連続時間上の最短距離を計算
- ショーケースごとにブラウザ自動保存、JSONファイル出力・読み込み
- Vercel + Supabaseによるクラウド保存、閲覧リンク（読み取り専用）、編集用リンク

## まずPCで試す（クラウド設定不要）

ターミナルから次を実行します。

```bash
cd StageFormation
python3 -m http.server 8000 --directory public
```

ブラウザで http://localhost:8000 を開きます。サンプル作品から操作できます。**クラウド共有ボタンだけは設定完了まで利用不可**です。

## GitHub + Vercel + Supabase で公開

1. Supabase（https://supabase.com/）で新規プロジェクトを作る。
2. Supabase の **SQL Editor** を開いて、同梱の `supabase.sql` のSQL全文を実行する。
3. Supabase の **Settings > API Keys** で **Secret key（`sb_secret_...`）** を取得。**公開可能な publishable key とは別です。**
4. Supabase の **Project URL**（例： `https://xxx.supabase.co` ）を確認する。
5. このフォルダの中身を GitHub リポジトリのルートへアップロードする。`.env` やSecret keyはGitHubへ入れない。
6. Vercel（https://vercel.com/）でそのGitHubリポジトリを **Import**。Framework Presetは `Other`、Root Directoryはリポジトリのルート、Output Directoryは空欄（デフォルト）のまま。
7. Vercelの **Project > Settings > Environment Variables** に以下の2つを追加：

   - `SUPABASE_URL` : SupabaseのProject URL
   - `SUPABASE_SECRET_KEY` : SupabaseのSecret key

8. **Redeploy** する。
9. Vercel公開URLからアプリを開く。「共有」→「クラウドに保存して共有リンクを作成」が動けば完了。

**大切：** Secret keyはVercelの環境変数だけに設定します。ブラウザコード、GitHub、共有リンクに含めないでください。

## 使い方

1. 左サイドバーでステージ横幅・奥行・バミリ間隔・客席の向きを設定。
2. 「＋追加」でダンサーを作り、左側で名前と色を編集。
3. ステージ上の丸をドラッグして0秒時点の立ち位置を作る。
4. タイムラインで8秒などに移動し「＋現在秒を登録」を押す。
5. 丸を移動して8秒時点の立ち位置を作る。以後必要な秒数を追加。
6. 「▶」で移動を再生する。「+1s」「−1s」で1秒ずつ確認。
7. 右サイドバーでダンサー間の接近候補を確認。動線の途中に回避位置を入れたい場合は途中の秒を登録して編集。
8. 「JSON保存」でバックアップする。共有したい場合は「共有」で閲覧URLを発行する。

### 閲覧リンクと編集リンク

- 閲覧リンク：URLを知る人が内容を閲覧できますが、変更はできません。
- 編集リンク：URLに秘密の編集キーが含まれます。キーを知る人は変更できるため、取り扱いに注意してください。
- 同じブラウザでは編集キーを保存しますが、別端末では編集リンクが必要です。
- アカウント認証は未実装です。同時編集は非対応で、後に保存した内容が優先されます。
- URLを知る人への公開に向く設計です。厳密なアクセス制限が必要なイベントでは、認証や招待設定を追加する必要があります。
- 公開したクラウド作品の削除機能は初版未搭載です。作品一覧の「削除」は**この端末の一覧から消す操作のみ**です。

### 移動経路の判定に関する注意

補間は直線・等速移動の仮定です。警告は人どうしの中心間距離を基準に、直線・等速移動時の連続時間上の最短距離を計算します。人の体格、腕の広がり、速度変化、実際の振付を再現しないため、安全性を保証しません。移動の回避経路を登録するには途中時刻のキーフレームを増やしてください。

## v1.2 MP3音源同期
タイムラインの「MP3を選択」から音声ファイルを選択します。同期チェックがオンの場合、音源の再生時刻を基準に立ち位置を表示します。再生・停止・1秒送り・スライダー移動は音源位置と連動します。「曲の長さに合わせる」で上限600秒の範囲で尺を設定できます。

**重要:** MP3本体はブラウザ内の一時URLで再生し、クラウド・JSONには保存されません。ショーケースを再度開く場合や共有先では、各自MP3を選択し直してください。立ち位置の登録は整数秒単位のままです。


## v1.3 MP3のクラウド共有
1. Supabase Dashboard > Storage で `stageflow-audio` という **Private** bucket を作成。最大50MB、MIME `audio/mpeg`。
2. Vercelの環境変数 `SUPABASE_URL` と `SUPABASE_SECRET_KEY` を設定し再デプロイ（既存の作品共有と同じ）。秘密鍵をブラウザに置かないでください。
3. 編集者が共有作品を開きMP3を選択すると、ブラウザからSupabase Storageへ署名付きURLで直接アップロードします。未公開作品は「共有」操作で公開後にアップロードします。
4. 閲覧URLを開くとサーバーが期限1時間の署名付き再生URLを発行し、音源を自動ロードします。再生ボタンをタップすると音声と立ち位置が同期します（スマホの自動再生制限のため自動再生開始はしません）。
5. 音源を解除すると作品側の参照が解除されます。Storage内の元ファイルは自動削除されないため、容量整理はSupabase Storageで行ってください。
6. 音源は**閲覧リンクを知る人が再生できる**設定です。権利者の許諾を得た音源のみアップロードしてください。閲覧URLの拡散には注意してください。
7. アップロードが失敗した場合は画面に失敗と表示されます。音声データ自体は端末内で再生できます。


## v1.4 バミリ基準のステージ表示
- 横幅・奥行きの数字は**バミリ数**です。1バミリは90cm（0.9m）として内部換算します。例えば横14なら12.6mです。
- バミリ間隔は固定90cm、中央の横位置は0です。出演者座標もバミリ単位で保存します。
- 「客席側：画面下／画面上」を切り替えると、ステージ図・既存の出演者・全キーフレーム・導線が上下反転して表示されます。客席からの距離を保つため、内部座標は変更しません。
- 旧版のm単位データは読み込み時にバミリ単位へ変換します。移行前にJSONをバックアップしてください。
